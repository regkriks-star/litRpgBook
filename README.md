# Ленивое мужество

Графическая новелла по роману Харитона Мамбурина: иллюстрированный пролог, полные главы 1–5 и начало главы 8 с двумя пошаговыми боями. На главном экране — оглавление с отдельными кнопками частей. Третья глава включает ремонт крыш, охоту с дубинкой, развитие героя и торговлю; главы 2–5 можно читать последовательно. Глава 4 включает испытание ножа, поездку к Ичиро, назначение мыши дамой, усиленную охоту и события в трактире. Глава 5 — дуэль с Уогунном, покупка топора, обучение и побег из храма Датарис. Мач и Саяка стоят слева, скорпионы — справа. Боевые реплики появляются над героями в пузырях. HP, MP и яд показаны рядом с каждым участником.

## Действия книги в геймплее

Каждое описанное в книге действие, которое можно обыграть геймплейно, должно выполняться через геймплей вместе с показом исходного текста. Особенно это касается взаимодействия с интерфейсом и объектами: игрок открывает окна, выбирает карточки, меняет параметры, вводит данные, осматривает, берёт и применяет предметы и видит результат своих действий. Для самостоятельных взаимодействий героя одного текста, автоматической анимации или нажатия «Далее» недостаточно. При этом просьбы героя к другому персонажу исполняются в постановке по ходу диалога: в первой главе богиня сама фильтрует карты, создаёт внешность и вводит названное героем имя. Существующая постановка первой главы правильная; кнопки фильтров и ручной ввод имени игроком не нужны. Книжная последовательность, результат событий и полный исходный текст сохраняются.

Нестандартные события, которые можно выразительно показать без участия игрока, сопровождаются уникальными анимациями по смыслу действия. Эталон — появление, раскрытие и последовательная фильтрация карт в первой главе: текст сопровождается действиями самих объектов и видимым результатом. Дополнительные кнопки для такой постановки не нужны.

[Примеры из существующих глав](docs/guides/gameplay-examples.md) показывают цепочку «кто действует → участие игрока или автоматическая постановка → видимый результат» и различают уже реализованный геймплей и необходимые доработки.

## Подготовка изображений

Перед генерацией изображения необходимо прочитать как минимум весь текст текущей главы до конца и определить все страницы, на которых его можно использовать. Затем спланировать расположение персонажей на каждой из этих страниц, включая их масштаб, позы, перемещения и место для текста. Только с учётом всей этой постановки составлять промпт изображения. Постоянные правила работы над проектом описаны в [AGENTS.md](AGENTS.md).

Предметы инвентаря, добычи и обмена должны использовать сгенерированные растровые рисунки в стиле игры. Перед генерацией изучить текущую и необходимые следующие главы, собрать перечень предметов и проверить готовые ресурсы. По умолчанию создавать общий тайлсет с прозрачным фоном и метаданными кадров, переиспользуя рисунки между сценами; SVG, библиотечные иконки и эмодзи не заменяют изображения предметов. Управляющие значки интерфейса могут оставаться векторными.

Перед постановкой движения составлять маршрут по связанным сценам и согласовывать фон, ракурс и направление спрайтов. Например, повозка Ичиро догоняет Мача сзади по дороге к Тантруму, везёт к воротам, затем проезжает внутрь, оставляя героя снаружи. Если готовый рисунок показывает обратное движение, нужен другой ракурс или фон; смена страницы не должна создавать необъяснимый разворот.

```sh

```

## Прохождение

**Оглавление → Глава 8 → прочитать завязку → Атака топором ×3 → Выждать → Прикрыть Саяку → Атака топором ×3 → После боя.** Реплики между действиями продвигаются кнопкой «Продолжить бой», пробелом или стрелкой вправо. Здоровье в финале: Мач 45/140, Саяка 48/96; предметы не расходуются.

[События книги, отличия игровых правил и таблица действий](docs/chapters/chapter-08.md). Эта же краткая инструкция доступна в игре по кнопке с перекрещенными мечами.

Все 26 абзацев выбранного фрагмента сохранены полностью, до разговора при записи в Гильдию. Сценарий извлечён из пользовательского FB2, реплики вместе с авторскими вставками показаны целиком за один шаг чтения, с исходными тире и пунктуацией. Диалоговые абзацы набраны Golos Text, повествование — Alegreya; это различие сохраняется в журнале. Длинный текст прокручивается внутри блока. Точный порядок атак на второго скорпиона книга не перечисляет; рекомендуемый игровой маршрут доводит описанные события до победы. Полный FB2 не входит в публичные файлы.

## Пролог

Все 15 абзацев из FB2 показаны без изменений и сокращений на 12 страницах, с сохранением курсива. Восемь иллюстраций меняются по событиям, текст расположен поверх фоновой иллюстрации. Длинные страницы прокручиваются; кнопки «Назад» / «Далее» и стрелки клавиатуры переключают страницы. В конце доступен переход к главе 1.

Место чтения хранится отдельно в `lazy-courage:prologue-page`, открытая часть — в `lazy-courage:view`. Возврат в оглавление не сбрасывает бой. «Читать пролог сначала» сбрасывает только страницу пролога. Извлечение текста: `python3 scripts/extract-story.py`.

[Дополнительные иллюстрации и места для них](docs/plans/improvements.md). [Первоначальные семь изображений](docs/prologue-art/README.md); [кадр Игараси и чистая квартира с отдельными фазами призыва](docs/art/sources/prologue-followup/README.md).

## Глава 1

Первая глава целиком: 113 полных абзацев FB2, от аудиенции у Датарис до отправки героя в Фиол. Существующие страницы 0–25 сохраняют свои номера.

Карты рассыпаны по сцене; нажатие приближает и переворачивает «Боевого алхимика». Фильтры убирают лишние карты по тексту, затем появляются «Рыцарь крови» и «Рыцарь Прекрасной Дамы». Заклинание меняет условие о смене дамы. Три божественных дара показаны одновременно: каждый можно рассмотреть, два неподходящих вызывают отдельные реакции героя. Книжный выбор остаётся «Чередой побед».

Некликабельный редактор внешности меняет цвета волос и глаз, затем показывает итоговый облик. Поле имени сначала пусто, «Мач Крайм» печатается на соответствующей реплике. Возрождение, восстановление на коленях и падение показаны отдельными позами; непрозрачная мозаика закрывает шорты на безопасном исходном рисунке. Всего у Датарис 12 поз, включая чтение журнала, смущение, хлопок, колдовство стоя и прощальный взмах.

Текст читается одновременно с действием; анимации не блокируют навигацию. При `prefers-reduced-motion` сохраняется итоговая постановка без движения. Кнопки и стрелки влево/вправо переключают целые абзацы; длинная реплика прокручивается в одном окне.

Отдельное сохранение `lazy-courage:chapter-one-page` не меняет прогресс пролога или боя. «Читать главу 1 сначала» сбрасывает только эту главу. [Промпты иллюстраций](docs/chapter-one-art/prompts.json), [постановка и рекомендации](docs/plans/improvements.md).

## Телефон и PWA

Все книжные и боевые сцены на телефоне работают горизонтально, включая 568 × 320. В портретном режиме появляется просьба повернуть устройство. Оглавление доступно в обеих ориентациях. Манифест допускает любую ориентацию; кнопка полного экрана в бою дополнительно запрашивает блокировку ориентации, если браузер её поддерживает.

Установка: меню браузера → «Установить приложение»; на iPhone — «Поделиться» → «На экран Домой». Поддерживающие установку браузеры также показывают кнопку «Установить игру» в настройках. Требуется HTTPS или localhost.

Офлайн-режим включён в production: после первой загрузки и сообщения «Готово к игре без интернета» доступны пролог, главы и весь боевой эпизод с изображениями, анимациями и шрифтами. Service worker создаётся при локальной сборке и поддерживает вложенные пути вроде `/episode/`. При каждом открытии, возврате из фона и восстановлении интернета игра проверяет новую версию без HTTP-кеша. После загрузки обновления во всех частях появляется предложение «Обновить» / «Позже». «Обновить» активирует подготовленную версию и перезапускает игру с сохранённым прогрессом; «Позже» скрывает предложение до следующего входа. Без интернета игра продолжает работать с уже загруженными ресурсами. В режиме Vite dev service worker не регистрируется.

Автосохранение использует `lazy-courage.save.v3`. Сохранения `v2` автоматически переносятся: фрагменты реплик объединяются, место чтения остаётся на том же абзаце. Сохраняются завершённые действия и текущая реплика. Перезагрузка во время анимации возвращает к предыдущему устойчивому состоянию. Старые сохранения `v1` остаются в браузере, но новая версия начинает расширенный эпизод заново: состав боя и сценарий изменились. Блокировка хранилища не мешает игре; статус сообщает, если сохранить прогресс не удалось.

## Проверки

Для тестов нужен локальный `ленивое мужество.fb2` в корне: он не хранится в Git.

```sh
npm test
npm run check:art
npm run check:kb
npm run test:e2e
npm run build
npx playwright test --config playwright.pwa.config.ts
```

`build` делает только локальную сборку и генерирует офлайн-кеш. Деплой: push в `main` запускает `.github/workflows/deploy.yml`, который собирает проект и публикует `dist` через GitHub Pages. Pages включается один раз вручную: Settings → Pages → Source: GitHub Actions. Адрес: https://regkriks-star.github.io/litRpgBook/. `GITHUB_TOKEN` не может включить Pages сам, поэтому первый деплой пройдёт после этого шага. Playwright использует `/usr/bin/google-chrome`; при переносе можно заменить путь установленным Chromium.

Публикация не заменяет проверки: сначала локальные тесты и сборка, затем push. Старый force-push в `gh-pages` удалён — сборку выполняет CI, исходники и история остаются в `main`.

Проверки охватывают весь маршрут, дословную полноту текста, цели атак, яд, лечение обоих героев, перехват, поражение и повторную попытку, восстановление диалогов, три размера горизонтального мобильного экрана, нарисованные кадры анимаций и офлайн-запуск с вложенного пути.
