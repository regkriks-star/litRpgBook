# Проверка и доказательства

Обновлено: 2026-11-27. Статус: активно.

Здесь — как проверять изменения и что считать доказательством. Правила мобильной проверки — в [low-screens.md](../guides/low-screens.md); обязательные инварианты — в [invariants.md](invariants.md).

## Окружение

* Node.js `^20.19.0 || >=22.12.0` — теперь зафиксировано в `package.json` `engines`. В текущем окружении проверено на Node 26.13.1.
* `npm ci` в чистом каталоге; не копировать `node_modules` между машинами.
* `check:art` больше не требует ImageMagick: встроенный парсер читает размеры WebP (RIFF/VP8/VP8L/VP8X).
* Playwright использует `/usr/bin/google-chrome`; при переносе заменить путь в конфиге.
* PWA-тесты запускают `vite preview` на 4173 с `--base /episode/`.

Если `npm test` падает с `tsx: not found`, а `esbuild` — с `EACCES`, значит `node_modules/.bin` и биты выполнения потеряны при распаковке. Лечится `npm ci`, а не правкой проекта.

В окружениях, где `$HOME` доступен только для чтения, `npm ci` падает с `EROFS` на `~/.npm/_cacache` и может оставить `node_modules` недособранным. Используй кэш внутри проекта:

```sh
rm -rf node_modules
mkdir -p tmp/npm-cache
npm ci --cache "$PWD/tmp/npm-cache" --no-audit --no-fund
```

`tmp/` уже в `.gitignore`. После установки проверь `node_modules/.bin/vite`, `node_modules/.bin/tsx` и бит `+x` у `node_modules/@esbuild/linux-x64/bin/esbuild`.

## Базовый набор

```sh
npm ci
npm test                 # 26 unit-тестов на 2026-11-20
npm run check:art        # 77 WebP, 28,03 MiB на 2026-11-20
npm run check:kb         # целостность этой базы
npm run typecheck        # tsc -b
npm run build            # tsc -b + vite build + dist/sw.js
npx playwright test      # story/E2E
npx playwright test --config playwright.pwa.config.ts
```

`npm run build` на 2026-11-20 предупреждает о чанке ~2,1 МБ — это известный долг, [KI-007](known-issues.md#ki-007-один-js-чанк-21-мб).

## Постановка главы 1

С 26.11.2026 трон Датарис и божественная печать используют общие переменные `.audience-scene` в `src/chapter-one.css`: печать концентрична опорной точке трона, а не отдельно стоящему кругу. Проверять на 1440 × 900, 1440 × 1000, 1280 × 600, 1024 × 600, 844 × 390 и 568 × 320, что фигура и жест руки остаются внутри круга, а окно текста не перекрывает кнопки; тест «throne anchors…» должен проходить без ручных поправок кадра. Снимки и метрики — [chapter-01-goddess-seal.md](../reviews/chapter-01-goddess-seal.md).

## Компактный низ окна чтения

С 27.11.2026 на экранах до 950 px в горизонтальной ориентации футер окна чтения показывает кнопки 26 px вместо 44, а окно получает больше места под текст. Проверять на 568 × 320 и 844 × 390: футер не выше 30 px, видимая кнопка 24–30 px, но `::after` не меньше 44 px и касание выше кнопки попадает в неё; на 1024 × 600, 1280 × 600 и 1440 × 900 кнопки остаются 44 px. Отчёт — [compact-reader-footer.md](../reviews/compact-reader-footer.md).

## Настройки чтения (все главы)

С 27.11.2026 кнопка «Настройки чтения» стоит в toolbar пролога, глав 1–5 и в меню главы 8 и открывает панель с тремя ползунками: шрифт 80–140 %, окно 80–120 %, прозрачность фона 0–65 %. Значения общие для книги, хранятся в `lazy-courage:reader-settings:v1` и появляются только после изменения. Проверять на 1440 × 900 и 568 × 320: кнопка 44 × 44, ползунки высотой не меньше 44 px, панель не выходит за экран и прокручивается, «Сбросить настройки» достижима, Escape и нажатие вне панели закрывают её, значения переживают перезагрузку и переход в другую главу, а при 100/100/0 окно совпадает с исходным. Новые главы подключают `.reader-surface` и `ReaderSettings` по [reader-settings.md](../guides/reader-settings.md). Снимки и метрики — [chapter-one-reader-settings.md](../reviews/chapter-one-reader-settings.md).

## Прямые нажатия на объекты

С 26.11.2026 действия с физическими предметами в главах 2–5 выполняются нажатием на сам рисунок через [SceneAction.tsx](../../src/SceneAction.tsx): куст, добыча, кристаллы, пакет, кролик, Ичиро, повозка, Оома, кот и мышь, волшебница, послушница. Проверять: у зоны нажатия не меньше 44 × 44 px, её центр не перекрыт `.c3-actions`, меню или окном текста и проходит `elementFromPoint`; объект виден без подписи, доступное имя и `title` сохраняют действие; клавиатурный фокус и reduced motion показывают понятное состояние. Команды движения, боя и открытия меню остаются обычными кнопками. Снимки и метрики — [chapter-object-actions.md](../reviews/chapter-object-actions.md).

## Что считается доказательством

* Команда с кодом выхода и датой.
* Свежий снимок/метрика для мобильной правки; старый снимок не доказывает текущее состояние.
* Для касания — координата центра и `elementFromPoint`, а не успешный `locator.click` после автопрокрутки.
* Для текста — проверка полного абзаца, а не только начала.
* Для сейва — загрузка существующего сохранения, а не только новое прохождение.
* Для PWA — реальная работа без сети после установки, а не только зелёный build.

Результаты складывать в `docs/reviews/` (или `test-results*/` для сырых артефактов). Не выдавать план или прошлый отчёт за новую проверку.

## Известные флейки

* `tests/chapter-one.spec.ts:133` («throne anchors…») раньше падал из-за сдвига трона в кадре 0 и таймаута 60 с; 20.11.2026 сдвиг убран, тест получил 120 с и прошёл три раза подряд — [KI-008](known-issues.md#ki-008-флейк-теста-трона).
* Параллельные Playwright-запуски должны иметь разные `--output`, иначе артефакты удаляют друг друга.
* PWA-тесты нельзя запускать одновременно с пересборкой `dist`: Vite очищает каталог, service worker получает временный 404.

## Ограничения

* Chromium/Playwright не заменяют физический телефон и Safari.
* Проверка на 568 × 320 в эмуляции не гарантирует реальные safe-area и плотность пикселей.
* `check:art` проверяет размеры и регистрацию, но не художественное качество кадра.
* Аудит и тесты не подтверждают дословность FB2 без отдельной сверки источника.
