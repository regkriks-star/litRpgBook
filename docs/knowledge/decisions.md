## D-013. Dev-сервер только на loopback

**Статус.** accepted · **Дата.** 2026-11-20

**Контекст.** `npm run dev` слушал `0.0.0.0`, а Vite-middleware редактора сцен принимал запись JSON без аутентификации. В общей сети это позволяло перезаписать постановку.

**Решение.** `npm run dev` слушает `127.0.0.1`; для явного сетевого доступа есть `npm run dev:lan`. POST `/__scene-editor/*` требует корректный `Origin`; запросы без `Origin` отклоняются.

**Следствия.** Для проверки с другого устройства нужно осознанно запустить `dev:lan` и понимать риск. Тесты E2E используют localhost.

**Ссылки.** [vite.config.ts](../../vite.config.ts), [package.json](../../package.json), [KI-002](known-issues.md#ki-002-dev-редактор-без-аутентификации).

## D-012. База знаний как операционный слой

**Статус.** accepted · **Дата.** 2026-11-20

**Контекст.** Правила, планы и отчёты существуют, но перед правкой приходится заново собирать маршрут; инженерные находки аудита не имеют общего реестра.

**Решение.** Добавлен `docs/knowledge/` с маршрутами, инвариантами, рецептами, решениями, глоссарием и реестром `KI`. База связана с `AGENTS.md`, `docs/README.md` и проверяется `npm run check:kb`. После задач база обновляется и получает запись в `changelog.md`.

**Следствия.** Нельзя дублировать в базе главы/планы; при расхождении прав код и профильный документ. Задача не считается завершённой без обновления затронутого раздела базы.

**Ссылки.** [README базы](README.md), [changelog](changelog.md).

## D-011. Инженерные проблемы отделены от улучшений глав

**Статус.** accepted · **Дата.** 2026-11-20

**Контекст.** Улучшения уровней 2–3 живут в `docs/plans/improvements.md`; аудит выявил другой класс задач — Git, безопасность dev-сервера, бандл, тесты.

**Решение.** Инженерные дефекты ведутся как `KI-NNN` в [known-issues.md](known-issues.md); улучшения контента остаются в `docs/plans/improvements.md`.

**Следствия.** Нельзя прятать инженерный дефект в список «полировки» и нельзя выдавать улучшение главы за исправление инфраструктуры.

**Ссылки.** [known-issues.md](known-issues.md), [improvements.md](../plans/improvements.md).

## D-010. Разделение документации по статусу

**Статус.** accepted · **Дата.** 2026-10-06

**Контекст.** В одном списке смешивались реализованное, планы и исторические заметки.

**Решение.** `docs/chapters/` — реализованное; `docs/plans/` — будущее; `docs/reviews/` — доказательства с датой; `docs/archive/` — история. Карта — `docs/README.md`.

**Следствия.** План нельзя показывать как готовую функцию. Новые документы именуются `chapter-NN.md` / `prologue.md`.

**Ссылки.** [docs/README.md](../README.md).

## D-009. Без бэкенда, прогресс в localStorage

**Статус.** accepted · **Дата.** 2026-09-27

**Контекст.** Статическая публикация на GitHub Pages; нужны офлайн и простой запуск.

**Решение.** Текст и ресурсы статичны; прогресс хранится в `localStorage`; сохранения версионируются и валидируются на чтении.

**Следствия.** Нельзя вводить серверную зависимость без пересмотра публикации и PWA. Блокировка хранилища должна оставлять игру играбельной.

**Ссылки.** [game.ts](../../src/game.ts), [architecture.md](architecture.md).

## D-008. Публикация через GitHub Actions

**Статус.** accepted · **Дата.** 2026-11-25 · заменяет force-push в `gh-pages`

**Контекст.** Нельзя отправлять исходники, историю и лишние файлы на публичный хостинг.

**Решение.** `.github/workflows/deploy.yml` на push в `main` выполняет `npm ci && npm run build` и публикует `dist` через `actions/deploy-pages`. Pages работает с Source: GitHub Actions.

**Следствия.** Публикация не заменяет тесты; откат — `git revert` + push. Ветка `gh-pages` и force-push не используются.

**Ссылки.** [deploy.yml](../../.github/workflows/deploy.yml), [README](../../README.md#проверки).

## D-007. Главы загружаются статически одним бандлом

**Статус.** accepted, пересматривается · **Дата.** 2026-09-27

**Контекст.** Простота сборки; все главы — часть одного SPA.

**Решение.** `App.tsx` статически импортирует главы и их JSON; отдельно lazy-loaded только `SceneEditor`.

**Следствия.** Первый запуск скачивает весь контент; чанк ~2,1 МБ. Аудит предлагает lazy-главы — [KI-007](known-issues.md#ki-007-один-js-чанк-21-мб). Решение менять только вместе с проверкой первого запуска и PWA-кэша.

**Ссылки.** [App.tsx](../../src/App.tsx), [build-pwa.mjs](../../scripts/build-pwa.mjs).

## D-006. PWA прекеширует весь билд

**Статус.** accepted, пересматривается · **Дата.** 2026-10-06

**Контекст.** Нужно гарантировать офлайн-доступ ко всем частям после первой установки.

**Решение.** `build-pwa.mjs` включает в `ASSETS` все файлы `dist`; `cache.addAll` прогревает кэш целиком.

**Следствия.** Установка/обновление скачивает ~31 МБ; сбой любого ресурса отменяет установку. Аудит предлагает выборочный кэш — [KI-004](known-issues.md#ki-004-тяжёлая-мобильная-загрузка-и-pwa-кэш). Любое изменение требует PWA-тестов.

**Ссылки.** [build-pwa.mjs](../../scripts/build-pwa.mjs), [verification.md](verification.md).

## D-005. Общий реестр ресурсов и проверка размеров

**Статус.** accepted · **Дата.** 2026-09-27

**Контекст.** Изображения использовались из разных папок и пакетов; дубликаты и неверные кадры ломали постановку.

**Решение.** `src/assets.ts` — единственный реестр; `scripts/check-art.ts` проверяет уникальность путей, физические размеры, сетки и зарегистрированные кадры. Исходники и промпты — в `docs/`, не в `public/`.

**Следствия.** Новый WebP без регистрации валит `check:art`; размеры нельзя «подгонять» в коде.

**Ссылки.** [assets.ts](../../src/assets.ts), [art/README.md](../art/README.md).

## D-004. Редактор сцен: файл в dev, localStorage в production

**Статус.** accepted · **Дата.** 2026-10-06

**Контекст.** Нужно править постановку без ручного JSON и без сервера в production.

**Решение.** В dev `SceneEditor` пишет `src/scenes/chapter-0N.json` через Vite-middleware и всегда скачивает JSON; в production — только `localStorage` + скачивание. Схема проверяется `parseSceneChapter`.

**Следствия.** Production-редактор не меняет исходники. Dev-сервер и запись защищены решением [D-013](#d-013-dev-сервер-только-на-loopback); запросы без корректного `Origin` отклоняются.

**Ссылки.** [vite.config.ts](../../vite.config.ts), [SceneEditor.tsx](../../src/SceneEditor.tsx), [scene-editor.md](../guides/scene-editor.md).

## D-003. Независимые версионированные сохранения частей

**Статус.** accepted · **Дата.** 2026-09-27

**Контекст.** Части можно читать в любом порядке; поломка одного сейва не должна уничтожать остальные.

**Решение.** У пролога, глав 1–5 и боя главы 8 отдельные ключи; у глав 2–5 — `:v1`; у боя — `save.v3` с миграцией из v2. Каждый `read*Save` валидирует и при ошибке начинает часть безопасно.

**Следствия.** Нельзя связывать прогресс глав и нельзя менять формат без миграции/нового ключа.

**Ссылки.** [glossary.md](glossary.md), [game.ts](../../src/game.ts).

## D-002. Единый BookText и разделение шрифтов

**Статус.** accepted · **Дата.** 2026-09-29

**Контекст.** Прямая речь и авторские вставки должны различаться шрифтом внутри одного абзаца, не создавая новый шаг чтения.

**Решение.** Все книжные сцены, журнал и пузыри используют `BookText`; `bookTextParts` выделяет речь/повествование, `runs` сохраняют курсив/strong.

**Следствия.** Нельзя рендерить текст главы «своим» `<p>` без `BookText`; нельзя дробить абзац ради шрифта.

**Ссылки.** [BookText.tsx](../../src/BookText.tsx), [invariants.md](invariants.md).

## D-001. Только горизонтальный мобильный режим

**Статус.** accepted · **Дата.** 2026-09-29

**Контекст.** Портретная компоновка всех сцен и боя стоила бы отдельного набора макетов и тестов.

**Решение.** Поддерживается landscape; в портрете — предложение повернуть телефон. Оглавление доступно в обеих ориентациях.

**Следствия.** Не разрабатывать портретные макеты. Проверять 568 × 320 и 44 × 44 на всех экранах, включая главу 8; [KI-003](known-issues.md#ki-003-зоны-касания-в-главе-8-и-модальных-окнах) исправлена.

**Ссылки.** [styles.css](../../src/styles.css), [low-screens.md](../guides/low-screens.md).
