# База знаний проекта

Обновлено: 2026-11-20. Статус: активна.

Это операционная база знаний для человека и агента, который улучшает «Ленивое мужество». Она не заменяет главы, планы и отчёты, а помогает быстро найти нужный документ, не нарушить инварианты и не потерять уже принятые решения.

## С чего начинать

1. [AGENTS.md](../../AGENTS.md) — обязательные правила проекта.
2. [Карта документации](../README.md) — где что лежит.
3. Этот файл — выбрать маршрут по задаче.
4. Профильный документ из таблицы ниже, затем код и тесты.

Если база знаний расходится с кодом, тестами или профильным документом, **прав код и профильный документ**. Базу нужно исправить в той же задаче.

| [verification.md](verification.md) | Перед объявлением работы завершённой | Изменились команды, матрица, счётчики тестов или известные флейки |
| [decisions.md](decisions.md) | Когда выбираешь архитектурное или процессное решение | Принято долговременное решение; старое помечается superseded |
| [known-issues.md](known-issues.md) | При планировании инженерных работ и исправлений | Проблема взята в работу, исправлена, отклонена или изменилась |

## Как искать

```sh
grep -rn "ключевое слово" docs/knowledge
grep -rn "KI-00" docs/knowledge/known-issues.md
grep -rn "lazy-courage:" docs/knowledge docs/plans docs/reviews
```

Стабильные идентификаторы:

* `KI-NNN` — инженерная проблема в [known-issues.md](known-issues.md);
* `D-NNN` — решение в [decisions.md](decisions.md);
* `INV-NN` — инвариант в [invariants.md](invariants.md);
* `WF-NN` — рецепт в [workflows.md](workflows.md).

Не переименовывай существующие ID. Если запись устарела, меняй статус и добавляй ссылку на замену.

## Иерархия истины

1. **Код, конфиги и тесты** — фактическое поведение.
2. **`docs/chapters/`** — реализованное поведение и допущения адаптации.
3. **`docs/guides/`** — обязательный порядок работы.
4. **`docs/plans/`** — будущее; план не означает, что задача сделана.
5. **`docs/reviews/`** — доказательства на дату проверки, а не вечная гарантия.
6. **`docs/knowledge/`** — выжимка, маршруты и реестры; не источник истины о поведении.

Правило: одна задача — одно место для подробностей. В базе знаний даём короткую выжимку и ссылку, а не копию главы или плана.

## Правила обновления

Перед работой:

* найди задачу в таблице выше и прочитай профильный файл;
* проверь `known-issues.md`: возможно, проблема уже описана;
* проверь `decisions.md`: возможно, решение уже принято;
* для главы или сцены дополнительно прочитай `docs/guides/chapter-workflow.md` и нужную главу целиком.

Во время работы:

* не дублируй в базе текст главы, полный план или снимки отчёта;
* используй существующие ID и ключи из `glossary.md`, не угадывай;
* если решение меняет архитектуру, сначала добавь запись в `decisions.md`, затем код;
* если найден новый дефект, заведи `KI-NNN` со ссылкой на воспроизведение.

После работы:

* обнови затронутые файлы базы;
* добавь запись в `changelog.md` с датой и списком файлов;
* у исправленной проблемы поставь `fixed`, дату и ссылку на проверку;
* обнови `verification.md`, если изменились команды, счётчики или флейки;
* обнови `architecture.md`/`glossary.md`, если появился новый модуль, ключ или стабильный ID.

### Definition of done для базы

| Что изменилось | Что минимум обновить |
| --- | --- |
| Код главы, сцены, боя | `architecture.md` при смене потока; `changelog.md` |
| Сохранение или миграция | `glossary.md`, `workflows.md`, `verification.md` |
| Новый ресурс или предмет | `glossary.md`, `workflows.md`, `verification.md` |
| Мобильное поведение или доступность | `invariants.md`, `verification.md` |
| Инженерный дефект | `known-issues.md` |
| Архитектурное решение | `decisions.md` |
| Любое изменение базы | `changelog.md` |

## Границы

* **Главы** (`docs/chapters/`) описывают, что уже работает.
* **Планы** (`docs/plans/`) описывают будущее; задачи уровней 2–3 идут в `docs/plans/improvements.md`.
* **Отчёты** (`docs/reviews/`) хранят доказательства и дату.
* **База знаний** хранит маршруты, инварианты, решения, реестр инженерных проблем и глоссарий.
* Инженерные проблемы из `known-issues.md` не заменяют улучшения глав из `docs/plans/improvements.md`; это разные списки.
